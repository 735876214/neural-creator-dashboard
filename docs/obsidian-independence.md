# 脱离 Obsidian 的独立性评估报告

> 评估对象：neural-creator-dashboard（v0.7.0，含「六星座自动关联」改动，提交 fd43c40）
> 评估日期：2026-10-18

## 一、结论

**运行时不依赖 Obsidian，创作全流程在脱离 Obsidian 后有一个明确的功能缺口。**

note-api 把笔记目录当作普通的 Markdown 文件树读写：只使用 Node 自带模块（`node:http` / `node:sqlite` / `node:fs`），不调用任何 Obsidian API，不依赖 Obsidian 插件或其内部数据格式。整套看板（图谱、分析、检索、AI 能力、选题/草稿管理、AI 热点日报）在只有文件系统 + note-api 的环境下完整可用。

真正与 Obsidian 相关的是几项**通用约定**，而非 Obsidian 本身：

| 约定 | 是否 Obsidian 专属 | 说明 |
|---|---|---|
| YAML frontmatter | 否 | 通用 Markdown 惯例 |
| 文件夹分类（作品/选题/草稿/方法） | 否 | 按文件夹名规则识别，可用参数显式指定 |
| `[[双链]]` | 准专属 | Obsidian 语法，但解析是自己实现的（正则），不依赖 Obsidian |
| `#话题` 标签 | 否 | 通用 Markdown 惯例 |
| 附件引用 `![[图.png]]` | 准专属 | 同上，自实现解析 |
| 「文件名即标题」 | 准专属 | Obsidian 约定，但看板写回时同步改文件名，自洽 |

## 二、功能影响逐项评估

### 2.1 不受影响（脱离 Obsidian 后照常工作）

| 能力 | 依赖说明 |
|---|---|
| 数据读取与图谱推导 | 只读 vault 文件，`/api/data` 驱动 |
| 六星座自动关联 | 全部在 `buildGraph` 内由数据推导：目录归属、`[[双链]]`、选题来源（含标题回连）、发布为作品、热点依据、话题标签、概念提及、双向共振、同名概念桥、语义边 |
| 作品分析面板（收藏率、排名、共振） | 纯前端计算 |
| 本地检索 askGraph | 规则匹配，不联网 |
| AI 打标签/摘要、AI 问答（RAG） | 服务端调用，与编辑器无关 |
| AI 热点日报 + 自动筛选题 | 服务端定时任务，RSS → 日报 → 选题落盘 |
| 选题增删改、转草稿 | 看板内完成，写回 NAS，乐观锁保护 |
| 草稿写作（含 `[[` 双链补全） | 创作台编辑器自带补全与连接预览 |
| 保存链路（防抖、mtime 乐观锁、409 冲突、离线 outbox） | persist.js 独立实现 |
| 登录与会话 | note-api 自带，与 Obsidian 无关 |

### 2.2 受影响（脱离 Obsidian 后出现缺口）

| 能力 | 缺口 | 影响 |
|---|---|---|
| 新建方法笔记 / 新建作品 | 看板只有「编辑已有笔记正文」入口，没有创建方法笔记和作品的 UI | **最大缺口**。方法库和作品库无法从看板内增长，必须用任意编辑器手工建文件 |
| 作品指标填写 | 作品库整体只读 | 指标（views/saves 等）只能手工在 frontmatter 里写 |
| 附件管理 | 没有上传/插入图片视频的 UI | 图文创作在纯看板内走不通 |
| 模板、批量整理、文件移动 | 没有文件管理界面 | 需要文件管理器或任意编辑器配合 |
| 外部改名后的链接维护 | `[[双链]]` 按文件名解析；在 Obsidian 里改名会自动重写链接，在外部改名不会 | 会出现「未创建」ghost 节点（图谱会如实标注，不会静默断链） |
| 多端并发编辑 | 只有 409 冲突提示 + 服务端留底 `.trash/`，没有 diff/合并 UI | 冲突需要人工比对（服务端在 409 响应里带回对方内容） |
| 快速捕获灵感 | 无移动端/快捷入口 | 选题池的补充依赖桌面环境 |

**总体判断**：阅读、回顾、分析、AI 辅助这条「消费链」完全独立；生产链（写作品、建方法笔记、配图）目前默认由外部编辑器完成——Obsidian 是最顺手的一个，但不是必需的，VS Code + 任意 Markdown 插件、Typora 等同样可以承担。

## 三、已具备的解耦基础

1. **解析层自实现**：`server/vault.mjs` 的 frontmatter/标签/双链解析是独立正则实现，读的是纯 Markdown。
2. **写回层最小侵入**：`server/frontmatter.mjs` 只改动指定键和正文，保留其余格式，对任何 Markdown 编辑器都友好。
3. **关联自动化已完成**：本次改动后，话题、概念、热点来源、发布关系、语义边全部自动推导，不再需要 Obsidian 的链接维护功能来「养」图谱。
4. **导入脚本独立**：`npm run import` 支持任意 Markdown 文件夹 + 显式 `--works/--methods/--ideas/--drafts` 参数，文件夹命名不必遵循 Obsidian 惯例。
5. **双链补全内置**：创作台编辑器自带 `[[` 补全，写作时的链接体验不依赖 Obsidian。

## 四、提升方向（按优先级）

### P0：补齐「创建」入口

- 新建方法笔记：`server/index.mjs` 的 `createNote('note', …)` 已存在，补一条 `POST /api/note/new` 路由 + 前端表单即可。
- 新建作品 + 指标表单：同上，`KIND_DIR.post` 已定义；表单字段即 frontmatter 指标键。
- 这是脱离 Obsidian 后唯一「做不了」的核心动作，优先级最高。

### P0：附件上传与编辑器增强

- `POST /api/attachment`（写入 vault 附件目录，白名单扩展名）+ textarea 升级为带预览的编辑器。
- 完成后图文创作可以在纯看板内闭环。

### P1：稳定 ID 替代标题匹配

- 现状：选题↔草稿（`source` 存标题）、草稿↔作品（同名）都是标题匹配；已有归一化与缺省回连兜底，但同名内容理论上可能误连。
- 方向：frontmatter 写入 `id` / `sourceIdeaId`，图谱优先按 id、回退按标题；一次迁移脚本即可。

### P1：发布流程按钮

- 草稿一键移动 `03-创作台` → `02-作品库`（服务端已有 rename/move 能力），提示补指标、联动选题状态。
- 「发布为作品」边目前靠同名自动连，按钮让这步显式化。

### P1：文件监听 / SSE 自动刷新 ✅（已实现：/api/version 指纹轮询）

- ~~现状：`/api/data` 只在启动时取一次，外部编辑器改动后需手动刷新。~~
- 已落地：`GET /api/version` 返回 vault mtime 指纹，前端每 5s 轮询（页面不可见时暂停）；
  变化即 `refreshData()` 重建图谱并 toast 提示。自己刚写盘（4s 宽限）不误报；
  有未保存编辑的选题/草稿不会被外部刷新覆盖（persist.isPending 防护）。

### P1：冲突 diff 视图 ✅（已实现：DiffModal）

- 已落地：409 时弹出双栏行级 diff（NAS 版 vs 我的版本，纯前端 LCS，零依赖）；
  三个动作——采用 NAS 版本（放弃本地改动）/ 用我的版本覆盖 / 稍后处理。
  两处入口：顶部同步横幅「对比」按钮、阅读弹窗编辑态的「对比差异」（此前会把
  NAS 内容直接盖掉编辑框、丢用户输入，已修复）。

### P2：中性链接语法与生态导入

- 支持 `[标题](路径.md)` 相对路径链接作为 `[[双链]]` 的对等物，降低最后一处 Obsidian 语法依赖。
- Logseq / Notion 导出的适配器（复用 `readVault` 的分类管道）。

### P2：语义关联扩展到全部内容 ✅（提前落地）

- 已落地：`/api/ai/relate` 的 embedding 覆盖全部内容类型——方法笔记 / AI 日报 /
  个人知识库 / 作品 / 选题 / 草稿，节点 id 与前端图谱一致（post:/note:/personal:/idea:/draft:），
  「灵感↔作品」「制度↔通报」等跨星团语义边都能长出；语义边上限 200 → 400。
